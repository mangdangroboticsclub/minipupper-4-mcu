# Host tests

Unit tests for the firmware code that does not touch the ESP32: the robot ID
format and the key derivation (docs/ROBOT_IDENTITY_AND_KEYS.md). No board, no
ESP-IDF, no network — which is the point: CI can prove `K_v` without hardware.

```sh
idf.py host-test                 # shortcut, via idf_ext.py

# or by hand
cmake -S tools/host_tests -B build/host_tests
cmake --build build/host_tests
ctest --test-dir build/host_tests --output-on-failure
```

## What runs

| Test | What it checks |
|---|---|
| `unit` | the C tests in `tests/` |
| `python_selftest` | `tools/mpx_id.py selftest` — the §11 test-1 properties (100k generated IDs, every single-symbol substitution rejected, the §6.3 vectors) |
| `vectors_up_to_date` | `tools/vectors/identity.json` was regenerated after the last algorithm change |
| `id_cli_rejects_bad_ids` | `mpx_id.py check` exits non-zero on a bad ID |

## Adding a test

Drop a `tests/test_<thing>.c` in and it is picked up (the CMake glob uses
`CONFIGURE_DEPENDS`):

```c
#include "test_harness.h"

TEST_CASE(id_accepts_the_doc_vector)
{
    CHECK(mpx_id_is_valid("MPX-AJZ7J8Y0YTDS"));
}
```

`CHECK`, `CHECK_MSG`, `CHECK_EQ_INT`, `CHECK_EQ_STR` and `CHECK_EQ_MEM` abort
the current test and record a failure; the rest of the suite still runs. The
exact failure is printed as `file:line: what`, so no separate report is needed.

## The one rule

Everything compiled into `mpx_host_tests` must be ESP-free. If a file includes
an `esp_*.h` header it does not belong here — and, more importantly, if the
algorithm lives in such a file it cannot be tested without a board. So
`mpx_id.c` and `mpx_derive.c` take the secret and an HMAC callback as
arguments; `mpx_identity.cc` is the thin ESP adapter that supplies
`esp_hmac_calculate` and the eFuse reads. The tests supply `mbedtls_md_hmac`,
or the shared code is called with the vector's key material directly.

## Golden vectors

`tools/vectors/identity.json` is generated by `tools/mpx_id.py` and is the
single source of truth. `mpx_vectors.h` is generated from it at build time, so
the C tests need no JSON parser. Changing the algorithm means:

```sh
tools/mpx_id.py vectors      # regenerate the JSON
idf.py host-test             # and update the C side if it breaks
```
